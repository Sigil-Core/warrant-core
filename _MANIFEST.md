# Repository manifest: @sigilcore/warrant-core

## Tier 1: always read

- `AGENTS.md`: package boundary, compatibility rules, and release constraints.
- `README.md`: public API contract, runtime support, and canonicalization profiles.
- `package.json`: package name, exact version, exports, scripts, and npm publication configuration.
- `SECURITY.md`: disclosure process and security boundary.

## Tier 2: read for the relevant work

- `src/`: parsing, canonicalization, commitments, signature handling, types, and runtime adapters.
- `test/`: golden vectors and tri-runtime parity tests.
- `scripts/verify-sigil-sign-parity.mjs`: local differential gate against the pinned Sigil Sign parser build.
- `vitest.config.ts`: Node runtime test configuration.
- `vitest.browser.config.ts`: Chromium browser-runtime test configuration.
- `vitest.workers.config.ts`: Cloudflare `workerd` test configuration.
- `.github/workflows/ci.yml`: CI contract for Node 22 and Node 24.
- `.github/workflows/publish.yml`: npm OIDC trusted-publishing release gate.

## Tier 3: generated output

- `dist/`: generated by `npm run build`. Do not edit it directly.

## Repository invariants

- The public package remains runtime-neutral at its root entry point.
- A canonicalization profile is an explicit compatibility contract.
- Runtime adapters implement the same byte and digest contracts.
- Published versions are immutable. Security-sensitive consumers pin an exact version.
